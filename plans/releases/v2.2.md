# v2.2 — Prove it against reality

**Status:** 📋 planned (v3 roadmap — see [docs/ROADMAP_V3.md](../../docs/ROADMAP_V3.md))
**Theme:** *Prove it against reality* — convert "wired + mock/single-node tested" into "verified against the real thing."
**Depends on:** **v2.1 must be merged + CI green on a clean machine** (the `enforce()` tool-call hook live in `agent/host.ts`+`adapter.ts`, branch-protection CI in `.github/workflows/`, the node-sound convergence lock in `convergence/lock.ts`+`scale/`). v2.2 verifies exactly what v2.1 wired; it must not start until that wall stands.

---

## Goals

1. Convert "wired + mock/single-node tested" into **"verified against the real thing"** — at least one **real** ACP agent, real LiveKit, real OIDC, real Postgres, and a real 2-node Redis cluster, all booting and passing a happy-path assertion.
2. Make the **BYO-key real-agent path first-class** — not a sketch that silently falls back to the mock. The default for a configured key is "you get a real agent or a clear, actionable error," never a fake one.
3. Give the operator **eyes and survival controls**: structured logs, health/readiness, a Prometheus-text `/metrics`, and a spend/iteration governor that can hard-kill a runaway agent and audit it.

This is where **Risk #1 (the runtime-verification mirage)** lives. The whole value prop is self-hosting real infra + a real agent; "works against a mock" is not a credible production signal. The real ACP path is exactly where reality bites: off-the-shelf agents (Claude Code / Codex / Gemini) assume a raw filesystem, and ICE redirects every read/write through the Yjs doc via `apps/server/src/agent/acp-backend.ts` → `apps/server/src/agent/adapter.ts`. If that adapter cracks under a real agent, **the finding reorders the roadmap — it is the true scope of v3, not a side quest** (see Open Questions).

## Demo / Definition of Done (sharp + testable)

On a maintainer box with real secrets in `.env`, a single operator can:

1. **`docker compose -f docker-compose.yml -f docker-compose.real.yml up --build`** boots ICE plus a containerized IdP (Keycloak/Dex), Postgres-as-primary, and a 2-node ICE deployment behind real Redis.
2. Run `pnpm ice:doctor` (or `node apps/server/src/agent/doctor.ts`) and see it **detect** an installed ACP backend (e.g. `claude-code-acp` on PATH), **validate the key** with a live "write one line to a scratch file through the Yjs doc" round-trip, and print a green report — or a precise remediation if a backend/key is missing. It **never reports a mock as if it were real.**
3. Create a room, spawn a **real** ACP agent (`POST /api/rooms/:id/agent { kind:'claude-code' }`), `@`-mention it to "add a function to `src/util.ts`", and watch the edit land in the live doc through the real adapter + the v2.1-enforced policy + the approval gate.
4. Join voice (LiveKit token → real SFU join succeeds), log in via the containerized OIDC IdP, and confirm room metadata is persisted in **Postgres**.
5. Open a second browser against the **second** node and see the same room converge; commit from node A and confirm node B's flush is serialized correctly (the v2.1 lock invariant holds across nodes).
6. `curl http://localhost:8080/healthz` → 200, `curl .../readyz` → 200 once dependencies are reachable, `curl .../metrics` → Prometheus text exposing `ice_rooms`, `ice_agents_active`, `ice_sync_messages_total`, `ice_commit_latency_seconds`, `ice_flush_latency_seconds`, `ice_approval_gate_hits_total`, `ice_policy_deny_total`, `ice_agent_kills_total`.
7. Set a tiny per-agent budget, send a prompt that loops, and watch the **spend/iteration governor hard-kill the agent**, surface the kill in the Squad UI, write an audit entry, and bump `ice_agent_kills_total`.
8. Follow the **README quickstart verbatim** on a clean machine and reach a real second cursor + a real agent edit with no "not yet wired up" dead ends.

**Hard release gates (all must hold to tag v2.2):**

- ✅ **≥1 real ACP agent backend drives a room end-to-end through the real adapter/policy/approval/convergence path.** Manual on a maintainer box is acceptable and recorded in PROGRESS.md; **"still mock-only" is NOT** acceptable.
- ✅ The **replayable ACP transcript harness** runs **keyless in CI** and exercises the same adapter→policy→approval→convergence code path the real agent does.
- ✅ The real-service integration tier boots and asserts happy-path for: ≥1 real agent, LiveKit (token→join), OIDC vs a containerized IdP, Postgres-as-primary, and a 2-node real-Redis cluster validating cross-node sync **and** the v2.1 lock invariant.
- ✅ `/metrics` + `/healthz` + `/readyz` + correlation-id structured logs exist and are scraped in the demo.
- ✅ The governor hard-kills a runaway and audits it.
- ✅ The README quickstart is executed top-to-bottom on a clean machine as part of release sign-off.

**Adoption metric (the real success signal):** *time-from-`git clone` to second-cursor-with-a-real-agent.* Record it in PROGRESS.md at sign-off.

## Scope — IN

- **[new · P0]** **Replayable ACP transcript harness** — record one real `claude-code-acp` / `codex-acp` session over stdio once, persist the ND-JSON ACP frames as a fixture, and replay them deterministically so the **adapter + v2.1 policy enforcement + approval gate + convergence** path runs **keyless in CI**. This is the load-bearing slice: it makes the otherwise-BYO-key real path CI-testable.
- **[debt · P0]** **Real-service integration tier** — `docker-compose.real.yml` overlay + BYO-secret wiring + an opt-in integration suite that boots and asserts happy-path for ≥1 **real** ACP agent end-to-end, **LiveKit** (token→join), **OIDC** vs a containerized IdP, **Postgres**-as-primary, and a **2-node real-Redis** cluster validating cross-node sync **AND** the v2.1 lock invariant. **≥1 real-agent backend is a HARD release gate.**
- **[debt · P0]** **First real exercise + hardening of the BYO-key `LlmPlanner`** (`apps/server/src/orchestrator/planner.ts`) — wire a concrete `PlannerLlmClient` to a real provider behind a key, exercise it against a real model, harden the JSON parse/validate/fallback path (timeouts, partial/garbage output, the distinct-file invariant), and prove the mock fallback still degrades gracefully keyless in CI.
- **[new · P1]** **BYO-key onboarding wizard + `doctor`/verify command** — detect installed ACP backends (`resolveAcpSpawn` extended to a probe), validate the key with a live "write one line through the doc" round-trip, and **replace the silent mock-fallback** with an explicit, operator-chosen decision. Plus a fixed, **TESTED** README quickstart.
- **[debt · P1]** **Minimal observability** — structured logs + a per-request/per-run **correlation id**, `/healthz` (liveness) + `/readyz` (dependency readiness), and a Prometheus-text **`/metrics`** surface (rooms, active agents, sync rate, commit+flush latency, approval-gate hits, policy-deny count, agent kills). **NOT a dashboard product.**
- **[new · P1]** **Provider spend + iteration/concurrency GOVERNOR** — per-room/per-agent **token + cost + loop/iteration budgets** with a **hard kill + audit** on breach, surfaced in the Squad UI and `/metrics`.

## Scope — OUT (deferred + why)

| Deferred | Where | Why |
|---|---|---|

| Heavyweight observability (Grafana/Prometheus-as-default/tracing), admin dashboard | charter (ROADMAP_V3 OUT; ADR-010 spirit) | v2.2 observability is deliberately the **seams the operator owns** (logs + `/metrics` + health), not a product. |
| Own model / inference gateway / ICE-managed-keys proxy | charter (ADR-004) | BYO-key via ACP stays the model. The governor may *read* usage and (optionally) front the user's OWN gateway for spend caps, but ICE never ships inference. |

| Per-file ACLs / RBAC / SSO-SAML / SCIM / multi-tenant | charter (ADR-009) | v2.2 *verifies* OIDC + owner/member roles against a real IdP; it does not grow them. The per-**agent** policy engine (v2.1) is the access-control work that matters. |
| Auto-running the real-service tier in hosted CI | this release | The real tier is **gated/opt-in** (needs keys/SFU/IdP); it runs on a maintainer box or a self-hosted runner with secrets. CI runs only the **keyless** transcript-replay + mock paths. v3.0 promotes a maintained subset.

## Build slices (worktree-isolatable)

Five slices, fanned out as worktree-isolated workflows per [AGENT_HANDOFF.md](../../docs/AGENT_HANDOFF.md). Each owns disjoint files and decouples from siblings through an **injected interface** (the v0.1→v2.0 idiom: a tiny seam + a default wired by the driver, so tests/CI never need the real dependency). **Slice A is load-bearing** — every other slice's "is the real path actually exercised?" claim depends on it.

### Slice A — ACP transcript record/replay harness **(LOAD-BEARING)**
**Owns (new):**
- `apps/server/src/agent/transcript/record.ts` — a CLI/util that connects to a real ACP child (reusing `resolveAcpSpawn` from `acp-backend.ts`), tees the ND-JSON frames in both directions to a fixture file.
- `apps/server/src/agent/transcript/replay.ts` — a `ReplayTransport` that re-emits recorded agent→client frames over the SAME `ndJsonStream`/`ClientSideConnection` seam `AcpAgentBackend` already uses, deterministically and keyless.
- `apps/server/src/agent/transcript/fixtures/` — `*.ndjson` recordings (one happy-path edit, one approval-gate-on-destructive, one denied-by-policy) + a small `manifest.json`.
- `apps/server/src/agent/transcript/replay.test.ts` — drives `AcpAgentBackend` against a fixture through a real `YjsAgentAdapter` on a bare `Y.Doc`, asserting the doc mutates exactly as recorded **and** that a denied/gated call respects the v2.1 enforcement hook.
- `apps/web/scripts/v2_2-transcript-check.mjs` — e2e: spawn an agent over the route with the replay transport injected, assert the edit lands in the live doc (extends the `*-check.mjs` pattern).

**Exports:** `recordTranscript(spec, outPath)`, `class ReplayTransport`, `makeReplayBackendFactory(fixture): AgentBackendFactory`, `loadFixture(name)`.

**Decouples via:** the existing `AgentBackendFactory` + `AgentIntentSink` seams (`agent/types.ts`). The replay backend is just another `AgentBackendFactory` injected via `AgentHostDeps.backendFactory` (already used by `orchestrator/squad.ts` and overridable on `startAgentForRoom`). It imports **only** `@zed-industries/agent-client-protocol` + `node:stream` + the adapter's public types — never the live host singleton.

**Why load-bearing:** it is the only thing that turns "real ACP agent ran once on a laptop" into a CI-repeatable assertion against the real adapter/policy/approval/convergence code path. Slices B–E lean on it for their "the real seam is exercised" guarantees.

### Slice B — Real-service integration tier + LlmPlanner exercise
**Owns (new + edit):**
- `docker-compose.real.yml` (new) — overlay adding: a containerized OIDC IdP (Keycloak or Dex, pre-seeded realm + client matching the `ICE_OIDC_*` contract), `postgres:16` with a seeded DB, `redis:7`, and a **second** `server` replica (`server2`) sharing rooms via `REDIS_URL`. LiveKit already exists in `docker-compose.yml` (run without `--dev` here).
- `apps/server/test/integration/` (new dir, opt-in via `ICE_REAL_SERVICES=1`):
  - `real-agent.int.test.ts` — boots ≥1 real ACP agent (`ICE_AGENT_CMD` set), drives one edit end-to-end through the route → adapter → doc.
  - `livekit.int.test.ts` — mint a token via `getVoiceToken` against real `LIVEKIT_*`, then a headless join handshake.
  - `oidc.int.test.ts` — full `buildOidcRoutes` login→callback against the containerized IdP.
  - `postgres.int.test.ts` — `selectMetadataStore` resolves `PostgresMetadataStore`; create user/room/invite round-trip.
  - `redis-cluster.int.test.ts` — two `Server` instances + real Redis: a write on node A appears on node B; **the v2.1 lock invariant holds** (a flush on A and a flush on B serialize — no interleaved commit).
- `apps/server/src/orchestrator/llm-client.ts` (new) — a concrete `PlannerLlmClient` adapting a real BYO-key provider (Anthropic by default; gateway-routable) to the tiny `complete()` seam. Lazy provider import (mirrors `db-postgres.ts`'s lazy `pg`).
- `apps/server/src/orchestrator/planner.ts` (edit) — harden parse/validate/timeout; keep the keyless mock fallback; add tests for garbage/partial/timeout/duplicate-file output.
- `docs/INTEGRATION_TESTING.md` (new) — how to bring the tier up, which secrets, how to run the gated suite, the manual real-agent checklist.

**Exports:** `selectPlannerClient(env): PlannerLlmClient | undefined` (returns `undefined` keyless → `LlmPlanner` uses the mock).

**Decouples via:** every real dependency already has an **env-gated null/503 seam** — `maybeRedisExtension` (REDIS_URL), `resolveVoiceConfig` (LIVEKIT_*), `readOidcEnv` (ICE_OIDC_*), `selectMetadataStore`/`isPostgresUrl` (DATABASE_URL), `resolveAcpSpawn` (ICE_AGENT_CMD). Slice B sets those env vars in compose/CI-secret context and asserts; it changes **no** production code path except the planner hardening (additive) and a `complete()` adapter behind an injected seam. Tests are guarded by `ICE_REAL_SERVICES` so the default `pnpm test` (CI) never touches them.

### Slice C — BYO-key onboarding wizard + `doctor` + tested quickstart

**Exports:** `probeAcpBackends`, `verifyAgentKey`, `AgentDoctorReport`.

**Decouples via:** `doctor.ts` depends only on the agent module's public surface (`AcpAgentBackend`, `resolveAcpSpawn`, `YjsAgentAdapter`) and an injectable transport (Slice A) — it never imports the host singleton. - `apps/server/src/api.ts` (edit) — mount `GET /healthz`, `GET /readyz`, `GET /metrics` (un-gated by the `/api/*` auth middleware) + apply the correlation-id middleware.
- Thin metric call-sites (edit, one line each at the existing seam): `convergence/convergence.ts` (`flushAndCommit` latency + commit count), `agent/adapter.ts` (`recordPending` → approval-gate-hit), the v2.1 `enforce()` deny site (policy-deny count), `realtime.ts` (sync message count via a Hocuspocus hook).

**Decouples via:** metrics is a **passive global sink** — call-sites do `metrics.incr('ice_commit_latency_seconds', …)` with zero behavioral coupling; if the sink is absent the call is a no-op. Other slices that want to emit a metric just import `metrics`; they don't depend on D's routes existing.

### Slice E — Spend / iteration / concurrency governor
**Owns (new + edit):**
- `apps/server/src/agent-policy/governor.ts` (new) — `class SpendGovernor`: per-(room, agent) running tallies of `tokens`, `costUsd`, `iterations`, plus a concurrency cap; `record(usage)` updates tallies; `check()` returns `{ over: 'tokens'|'cost'|'iterations'|'concurrency' }` on breach. Sibling to the existing `agent-policy/policy.ts` (same module, same "pure decision layer" shape).
- `apps/server/src/agent-policy/governor.test.ts` (new).
- `apps/server/src/agent/host.ts` (edit, small) — on each turn/tool-call, `governor.record(...)`; on breach call existing `interruptAgent` + `stopAgent`, `recordAudit({ action:'agent-killed', detail:reason })`, and `metrics.incr('ice_agent_kills_total')`. Hook sits next to the v2.1 `enforce()` call so kill + enforce share the seam.
- `apps/server/src/api.ts` (edit, additive) — `PUT /api/rooms/:roomId/agents/:agentId/budget` (set budgets) + include current spend in the agent state surface for the UI.
- `packages/shared/src/agent.ts` (edit, additive type) — `AgentBudget { maxTokens?, maxCostUsd?, maxIterations?, maxConcurrent? }` + optional `spend` on the agent state.
- `apps/web/src/components/SquadPanel.tsx` (edit) — render per-agent spend vs budget + a "killed: budget exceeded" state.
- `apps/web/scripts/v2_2-governor-check.mjs` (new) — set a tiny budget, drive a looping mock agent, assert it is hard-killed, audited, and `ice_agent_kills_total` increments.

**Exports:** `class SpendGovernor`, `GovernorDecision`, `AgentUsage`.

**Decouples via:** the governor is a **pure tally/decision object** (no doc, no host imports) injected into the host exactly like the v2.1 `PolicyRegistry`/`enforce()` — the host owns the wiring, the governor owns the math. **Cross-slice contention map (kept disjoint):**
- `apps/server/src/api.ts` is touched by **C, D, E** — each adds **distinct, additive route blocks** (doctor route / health+metrics routes / budget route). Land them as separate commits in the established route region; the integration owner merges on the working branch (same as v0.1→v2.0). No shared handler is rewritten.
- `apps/server/src/agent/host.ts` is touched by **A** (only via the injected factory — no edit needed) and **E** (the governor hook). Keep E's edit to one localized block at the tool-call seam, beside v2.1's `enforce()` call.
- Everything else is slice-private.

## Sequencing + dependencies

**Cross-release gate (forced):** v2.2 starts only after **v2.1 is merged and CI is green on a clean machine** — the `enforce()` hook, the CI wall + branch protection, and the node-sound lock must exist. The transcript harness, the integration suite, and the governor all assert against v2.1's machinery; building them first would test a moving target.

**Intra-release order:**
1. **Slice A first (load-bearing).** Record fixtures from a real agent once on a maintainer box; land the replay transport + tests + the CI keyless job. Everything downstream uses it to be CI-testable. *Gate: `v2_2-transcript-check.mjs` green in CI keyless.*
2. **Slices C and D in parallel** (disjoint files; both lean on A — C for keyless `doctor` tests, D is independent). *Gate: doctor reports real-vs-mock explicitly; `/healthz`+`/readyz`+`/metrics` answer.*
3. **Slice E** after D exists (uses `metrics` + `recordAudit`; hooks `host.ts` beside v2.1's `enforce()`). *Gate: `v2_2-governor-check.mjs` proves a hard-kill + audit + metric.*
4. **Slice B last and deliberately** — it is the **gated** real-service work needing keys/SFU/IdP/Postgres/Redis. Bring up `docker-compose.real.yml`, run the `ICE_REAL_SERVICES=1` suite on a maintainer box / self-hosted runner, and **manually drive ≥1 real ACP agent end-to-end (the HARD GATE)**. The LlmPlanner real exercise rides here. *Gate: the real-service happy-path matrix + the manual real-agent run, recorded in PROGRESS.md.*

**Why A→{C,D}→E→B:** the cheap, CI-provable, keyless work (A, the harness) unblocks everything; the operator-eyes work (D) precedes the governor that emits through it (E); the expensive, secret-bearing, can't-fully-automate work (B) lands last so a green CI exists to catch regressions the manual run might miss.

**Hand-off to v2.3:** the v2.3 moat work (intent-locks / reviewer-agent / blame) MUST NOT begin until v2.2's real-agent gate is met. If Slice B surfaces an ACP↔Yjs adapter defect, that fix preempts v2.3 (see Risks).

## Test / verification strategy

**Unit (in `pnpm test`, keyless, CI-blocking):**
- `transcript/replay.test.ts` — replayed frames produce the exact recorded doc mutations; a `denied-by-policy` fixture is blocked by the v2.1 `enforce()` hook and never mutates the doc; a `gated-destructive` fixture parks on the approval gate and only applies on approve.
- `planner.test.ts` (extended) — `LlmPlanner` against a stub `PlannerLlmClient`: valid JSON → plan; garbage/partial/timeout/duplicate-target → graceful mock fallback + the distinct-file invariant preserved.
- `doctor.test.ts` — probe detects present / missing backends; `verifyAgentKey` via the replay transport reports `keyValid` without a real key.
- `metrics.test.ts` / `health.test.ts` — Prometheus render shape; `readyz` flips on a stubbed-unreachable dependency.

## Risks + mitigations (specific to v2.2)

1. **The real ACP agent meets "agents write through Yjs, never the FS" and the adapter cracks (Risk #1 — the whole reason this release exists).** Off-the-shelf agents assume a raw filesystem; `acp-backend.ts` redirects `fs/read`/`fs/write` to the doc and serves only `readTextFile`/`writeTextFile` capabilities — a real agent may attempt `fs/delete`, line-ranged edits, terminal writes, or out-of-band file access the adapter doesn't map. **Mitigation:** Slice A records a *real* session early so surprises surface before Slice B; the integration suite + manual run are a HARD GATE; **any adapter rework this surfaces is the true scope of v3 and reorders the roadmap (it preempts v2.3), not a side quest.** Capture the failure as a recorded fixture so the fix is regression-tested forever.
2. **"Verification theater" — the harness replays a sanitized capture that doesn't represent real agent behavior, so CI is green but reality still bites.** **Mitigation:** fixtures must come from genuine `claude-code-acp`/`codex-acp` runs (not hand-authored), include the awkward cases (destructive gate, denied-by-policy, multi-edit), and the HARD GATE is a *live* run, not just replay. The replay path asserts against the same `enforce()`/approval code the live path uses.
3. **The real-service tier is flaky/heavy and either blocks merges or gets skipped into irrelevance.** **Mitigation:** keep it strictly **opt-in/gated** (`ICE_REAL_SERVICES=1`); CI blocks only on the **keyless** transcript+mock+obs+governor scripts; the real tier runs on a maintainer box / self-hosted runner and its result is recorded at sign-off. v3.0 promotes a maintained subset — v2.2 doesn't over-invest in hosted-CI plumbing.
4. **The governor mis-fires — kills a healthy agent (cost estimation wrong) or fails to kill a runaway (token accounting lags).** Killing a teammate mid-edit is its own trust failure. **Mitigation:** the governor is a pure, unit-tested tally with deny-biased thresholds and an explicit `over` reason; the hard-kill always audits + surfaces in the UI (never silent); budgets are opt-in (no budget → no kill); the `v2_2-governor-check.mjs` e2e proves both the kill and the no-false-kill-under-budget cases.
5. **`/metrics` or `/healthz` accidentally sits behind the `/api/*` auth gate (returns 401) or leaks secrets.** **Mitigation:** mount health/metrics **before** the auth middleware in `api.ts`; `readyz`'s redis endpoint is credential-stripped (reuse `getScaleStatus`'s `safeEndpoint`); metrics expose only counts/latencies, never room content or keys.
6. **Cross-slice `api.ts` / `host.ts` collisions during the fan-out.** **Mitigation:** the contention map above — additive, disjoint route blocks; one localized governor hook beside v2.1's `enforce()`; integration on the working branch as in v0.1→v2.0.
7. **`LlmPlanner` real exercise tempts same-file/dependent-subtask decomposition (a charter-deferred moat item).** **Mitigation:** the planner stays a *router* that preserves the distinct-file invariant (parse-time enforced today); same-file LLM decomposition + agent memory remain **v3.x** (ROADMAP_V3 OUT). v2.2 hardens the existing shape; it does not grow it.
