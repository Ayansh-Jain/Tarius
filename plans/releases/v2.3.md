**Status:** 📋 planned (v3 roadmap — see [docs/ROADMAP_V3.md](../../docs/ROADMAP_V3.md))

## Demo / Definition of Done (sharp + testable)

Two browsers + one squad in a single room, on a clean `docker compose up` with the v2.2 BYO-key wizard pointing a real (or replayed) ACP agent at the room:

1. **Two agents work the same file without trampling.** A human starts an orchestration that (via the new collision hint) routes a coder + a reviewer toward `src/app.ts`. The coder broadcasts an advisory intent-lock on a line range; the reviewer's panel shows a colored "Coder working here (lines 12–40)" highlight and a **yield/queue** affordance; a human can **override** the lock. Crucially: kill the lock layer mid-edit (drop the awareness field) and **both writers keep editing losslessly** — the CRDT stays conflict-free; zero edits lost. *(Testable: `v2_3-intentlock-check.mjs` + `intent-lock.test.ts` degradation case.)*
2. **A reviewer-agent gates another agent's diff.** The coder proposes a destructive/whole-file change on the propose-then-apply path; a `reviewer`-role agent inspects the proposed diff, posts **structured findings** into agent chat, and **blocks at the existing approval gate** (or approves-with-comments). The human is the final arbiter — approving over a block still applies; the block is audited. *(Testable: `reviewer-gate.test.ts` + `v2_3-reviewer-check.mjs`.)*
3. **The gutter shows durable per-line human-vs-agent blame.** Reopen the file after a server restart: every line that an agent or human authored *this session and the last* shows the correct author swatch — blame is now read from a **persisted attribution layer**, not just live-session observation. *(Testable: `blame-store.test.ts` round-trips across a doc reload; `BlameView` renders persisted authors.)*
4. **Commits carry agent authorship.** When an agent's work is flushed/committed, the commit trailer contains `Co-Authored-By: <Agent display> <agent id>@ice.local` (and the in-UI history shows it). *(Testable: `convergence/git.test.ts` asserts the trailer; `SourceControl` history shows co-authors.)*
5. **The merge gate is a real per-hunk review surface.** Open the branch-diff review: side-by-side per-file/per-hunk **accept / reject**, each hunk labeled with **who/what authored it**, rendered with a shared **conflict-region primitive** (the same primitive v3.0's external-push merge reuses). *(Testable: `mergeReview.test.ts` over the hunk model; `MergeReview` component check.)*
6. **The Squad panel replays "what the squad did."** A run-record timeline (prompt → tool calls → approvals/denials → edits → commit) reconstructed **purely from `getAudit(doc)` + origin tags** — no new capture path. *(Testable: `runRecord.test.ts` reduces a synthetic audit array into an ordered timeline.)*
7. **First-5-minutes demo room.** `docker compose up` → open the seeded room → a checklist walks: second cursor → voice → @-mention the agent to add a function. A README GIF is captured from that exact flow. *(Testable: `v2_3-demo-room-check.mjs` asserts the seed repo + checklist doc exist on a fresh room.)*

**The whole release is gated by green CI** (the v2.1 wall): `pnpm typecheck && pnpm build && pnpm test` + every `apps/web/scripts/*-check.mjs` (including the four new v2.3 scripts) pass before merge.

**Non-negotiable safety invariant (Risk #3):** intent-locks are **advisory presence only**. They live on the **Yjs awareness channel**, never in the Y.Doc, and never block a write. If the lock layer fails, behavior degrades to today's conflict-free-but-uncoordinated editing — **never to data loss or deadlock.** If locks cannot be made provably safe under the chaos test, **ship Slice B (reviewer-agent) + Slice C/D/E and HOLD Slice A's same-file coordination** (reviewer-agent never touches data integrity).

## Goals
- Deepen the moat where it is genuinely thin: multiple writers safely **coordinating** in the SAME buffer — the gap the worktree-isolation crowd structurally cannot copy.
- Make every agent action **legible after the fact**: durable blame, agent commit authorship, a replayable run-record.
- Give humans a **real review surface** (reviewer-agent + per-hunk merge gate) before agent work becomes history.
- Build it **entirely on the substrate ICE already owns** — awareness (`connection.ts`), origin tags (`transactWithOrigin`/`EditOrigin`), the approval gate (`agent/adapter.ts`), `enforce()` (`agent-policy/`), and `getAudit(doc)` — adding **no new pillar and no second coordination substrate** (charter; A2A stays declined, ADR-004 / `docs/A2A_EVALUATION.md`).

## Scope — IN
- **[new·P1]** **Soft intent-locks / turn-taking** over the Yjs **awareness** protocol (advisory, TTL'd region claims `"editing func X in foo.ts, lines a–b"`; yield/queue; colored "agent working here" highlights; human override) + an **orchestrator same-file-collision hint**. **ADVISORY ONLY — claims live in awareness, never the Y.Doc; the CRDT stays conflict-free; lock-layer failure degrades to today's behavior, never to data loss.**
- **[new·P1]** **Reviewer-agent gate** — a `reviewer`-role agent reviews another agent's proposed diff on the propose-then-apply path, posts structured findings into `getAgentChat(doc)`, and can **block at the existing v0.5 approval gate** or approve-with-comments; the human is the final arbiter. Reuses the gate + `enforce()` machinery (no new gate).
- **[debt·P2]** **Full per-line human-vs-agent blame** — promote the session-only `BlameView` into a **durable** origin-tag attribution layer persisted on the doc, rendered in the editor gutter + `BlameView`.
- **[debt·P2]** **Agent→git-commit authorship** end-to-end — originating identity in commit trailers (`Co-Authored-By` / agent id) + the in-UI git history.
- **[debt·P2]** Deepen the branch-diff **merge gate** from the light v1.0 cut (`SourceControl.tsx` commit+history) into a real review surface: side-by-side per-file/per-hunk accept/reject with "who/what authored each hunk," built on a shared in-editor **conflict-region primitive** (designed for v3.0 reuse).
- **[new·P2]** Agent **run-record / "replay my changes"** timeline in the Squad panel (a view over `getAudit(doc)` + origin tags; **no new capture path**).
- **[new·P2]** **"First 5 minutes" guided demo room** — seeded sample repo + onboarding checklist (second cursor → voice → @-mention the agent to add a function) + a short README GIF from that exact flow.

## Scope — OUT (deferred / not this release)
- **Live external-push 3-way merge** → **v3.0** (lands DEAD LAST; reuses this release's conflict-region primitive). v2.3 deliberately does **not** make `onLoadDocument` merge external pushes into a live room — the data-loss guard in `realtime.ts` stays.
- **Agent memory store + real-LLM same-file / dependent-subtask decomposition** → **v3.x**. Same-file decomposition *depends on intent-locks proving safe first*; do not ship the "clever broken moat." The orchestrator keeps pinning specialists to **distinct files** (conflict-free by construction, `orchestrator.ts`); v2.3 only adds an *advisory hint* when a collision is detected, never auto-decomposition.
- **A2A protocol / inter-agent message bus** — declined (ADR-004; `docs/A2A_EVALUATION.md`). The shared Y.Doc + orchestrator + these advisory intent-locks ARE the coordination substrate. **No second coordination mechanism.**
- **A new top-level Y.Doc key for locks** — locks are awareness-only. (Blame *does* add a doc-side attribution map; see Open Questions Q1.)
- **Full merge/conflict UX for git merges** (accept-theirs/keep-ours across a real 3-way) — v3.0. v2.3 ships only the *primitive* + the *branch-diff review* surface.
- **IDE-parity chrome** (debugger UI, LSP-everything) — the #1 named bloat trap (charter).

### Slice A (worktree) — intent-locks / turn-taking + collision hint  ⚠️ LOAD-BEARING (riskiest; the moat-depth claim)
**Owns:**
- `apps/web/src/lib/intentLocks.ts` (NEW) — the awareness-backed lock manager: `claim(filePath, fromLine, toLine, label, ttlMs)`, `release(id)`, `peers(): IntentLock[]` (other clients' live, non-expired claims), `onChange(fn)`. - `apps/server/src/orchestrator/collision.ts` (NEW) — pure helper `detectCollisions(planned, existingTargets)`: when two subtasks would target the same file, emit the advisory hint via the injected `onCollision` (Slice 0 seam). Posts an advisory note into `getAgentChat(doc)` / `getAudit(doc)` (`action:'collision-hint'`). **Never** reassigns or blocks — the orchestrator still pins distinct files; this only surfaces intent.
**Edits (small, well-fenced):** `apps/web/src/editor/Editor.tsx` (append the decoration extension to the `extensions` array — additive, behind the awareness field so it no-ops if absent); `apps/web/src/components/AgentsPanel.tsx` or `SquadPanel.tsx` (yield/queue affordance + override button — additive section). ## Sequencing & dependencies

**Cross-release gates (forced by the roadmap — Risk #2, #3, #4):**
1. **v2.1 CI must be green on a clean machine** AND **v2.2 must have verified the real-agent path** before **any** v2.3 slice starts. (No moat feature merges onto an un-walled base; the v2.1 `enforce()` hook is a hard prerequisite for Slice B, which extends exactly that seam.)
2. v2.3 ships **before** v3.0 and hands v3.0 two artifacts: the **conflict-region primitive** (`ConflictRegion.tsx` + `diff.ts`, Slice D) and the proof that **advisory intent-locks degrade safely** (Slice A chaos result). v3.0's live 3-way merge must not start until both are in hand.

**Intra-release order:**
1. **Slice 0 (main)** — contracts + `getBlame` key + injected seams. *Everything blocks on this.*
2. **Slices A, B, C, E fan out in parallel** (worktree-isolated; disjoint file ownership). **D may start in parallel** but its `authoredBy` annotation **integrates after C** (falls back to commit author until then).
3. **Integration order back to main:** C (blame + authorship; unblocks D's authored-by) → D (merge review) → B (reviewer-gate) → A (intent-locks; integrate last so the chaos/degradation test runs against the fully-wired editor) → E (views/seed; trivially mergeable any time).
4. **Gate to "done":** the full CI wall green (typecheck/build/test + all `*-check.mjs`, incl. the 4 new ones) + the intent-lock degradation/chaos test green + the reviewer-gate e2e green.

**Decoupling recap (how siblings don't collide):** A = awareness-only (no doc writes) + additive editor extension; B = injected `ReviewHook` seam, reuses the existing gate; C = self-contained `getBlame` observer + confined commit-message enrichment; D = pure shared diff model + new component tree + one additive read route; E = pure views + a seed. The only shared **edited** files are `ydoc.ts`/`index.ts` (Slice 0 only), `api.ts` (additive routes — assign disjoint route blocks per slice in Slice 0's stub to avoid merge conflicts), and `SquadPanel.tsx`/`AgentsPanel.tsx` (additive sections — partition by named section in Slice 0).

## Risks + mitigations (this release)
- **R3 — coordination overreach → deadlock/clobber (the headline risk).** *Mitigation (non-negotiable):* intent-locks are **advisory presence on awareness only**, never a write barrier, never in the Y.Doc. Built so failure *cannot* lose data (Slice A: zero doc writes; `peers()=[]` on bad input). The chaos test is the **gating bar**. **Fallback:** if locks can't be proven safe, ship B+C+D+E and **hold Slice A's same-file coordination** — B (reviewer) deepens the moat without touching data integrity.
- **Reviewer-agent becomes a hidden auto-rejecter / second gate.** *Mitigation:* the reviewer **only** routes a proposal onto the **existing** approval gate with findings attached (DoD #2); the **human is final arbiter** (approve-over-block applies). No new gate; reuses `enforce()`'s `require-approval` path. Test asserts approve-over-block applies.
- **Blame divergence / unbounded growth.** *Mitigation:* `getBlame(doc)` writes go through `{kind:'system'}` (never masquerade as the author) and are **capped/trimmed** like `audit/recorder.ts`; line-mapping reuses the already-tested `BlameView` delta math. Blame is best-effort attribution, **never** a correctness gate.
- **Conflict-region primitive bakes in the wrong shape for v3.0** (forcing a rewrite of the load-bearing merge). *Mitigation:* `diff.ts` is **pure** and the `Hunk` model is defined in `packages/shared` (Slice 0) against v3.0's stated needs; Q4 forces a v3.0-reuse review before D merges.
- **Co-Authored-By trailer breaks a real ACP agent's commit identity / clone.** *Mitigation:* `materializeAndCommit` already round-trips author/committer; trailers are appended to the **message** only (standard `Co-Authored-By:` convention), changing no git mechanics; covered by `convergence/git.test.ts`.
- **`api.ts` / `SquadPanel.tsx` merge conflicts across 5 worktrees.** *Mitigation:* Slice 0 pre-partitions `api.ts` route blocks and panel sections by named comment markers so each slice edits a disjoint region.
