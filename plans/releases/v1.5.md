# v1.5 — A squad of agents

**Status:** ✅ done (2026-05-31) — orchestrator, policy+snapshot, MCP, multi-agent UI; 4 slices merged, wired, verified e2e.
**Depends on:** v1.0 (the single-agent loop + trust surface must be loved first)
**Demo:** Assign a feature to an **orchestrator**; watch it route subtasks to an architect, a coder, and a debugger agent — all co-editing the same tree concurrently, each a distinct color, never trampling each other. Per-agent permissions block a tool an agent shouldn't use. Diff/blame shows exactly who (which human, which agent) wrote each line.

## Goals
- Deliver "multiple agents working together" — the moat — only now that the single-agent loop is loved.
- Treat one→many as a concurrency/permissions problem on the existing origin-tagged foundation, not a rewrite.
- Keep agents legible: you SEE who touched each line, live.

## Scope — IN
- Multiple ACP agents co-editing one tree concurrently with distinct identities/colors + per-agent attribution.
- Orchestrator routing subtasks to specialist roles (architect/coder/debugger, Kilo-style) working IN the shared workspace — watch & interrupt.
- Per-agent permission policies (allow/deny per tool, per path) + propose-then-apply for large refactors.
- MCP tool palette (workspace-scoped tools agents can call).
- Diff/blame distinguishing human vs each-agent authorship across history.
- Opt-in agent branch/snapshot "try it safely" mode that merges back into the room (the one good idea from the isolation camp, as an escape hatch).

## Scope — OUT
- Scale-out, Forgejo, governance (→ v2.0). A2A protocol (evaluate at v2.0).
