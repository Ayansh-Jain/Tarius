# v3.0 — Bidirectional convergence + audited trust contract

**Status:** 📋 planned (v3 roadmap — see [docs/ROADMAP_V3.md](../../docs/ROADMAP_V3.md)) — **the GA / trust release. Lands DEAD LAST.**
**Depends on (HARD gates, all must be green first):**
- **v2.1** — CI wall on every PR, per-tool-call policy **enforcement** live in `agent/`, **node-sound** convergence lock (`convergence/lock.ts` → Redis-lease or sticky-room), opt-in OS sandbox.
- **v2.2** — real-service tier proven (≥1 real ACP agent e2e), `/metrics`+`/healthz`, spend/iteration governor, replayable ACP transcript harness in CI.
- **v2.3** — the shared in-editor **conflict-region primitive** (built in v2.3 Slice D's merge gate) + durable per-line blame/origin attribution. **v3.0 Slice B reuses the conflict-region primitive verbatim — do not re-invent it.**

**Demo / DoD:** see the full [v3 Definition of Done](../../docs/ROADMAP_V3.md#definition-of-done--v30). In short: `docker compose up` on a clean machine → BYO-key wizard points a **real** ACP agent at a real repo → an outside `git push` lands into the **live** room (3-way merged, conflicts surfaced to a human, never auto-clobbered) → several humans co-edit → walk away overnight → come back to a workspace with **zero lost edits, no silently-wrong commits, every agent action attributable + enforced, multi-node sound** — all behind green CI + a closed external OWASP/STRIDE audit, with the stress-proof + audit published as the trust artifact.

This release changes the trust **contract**; it ships almost no new product surface. The one genuinely new runtime path is the external-push live merge (Slice A) — the item that completes the convergence seam (ADR-000) and the one item that can break the law it serves, hence its DEAD-LAST sequencing on a hardened base, gated by the chaos harness (Slice C).

## Goals
- Make the git-in-the-box pillar truly **two-way**: an external push lands live into an open room without losing either side, conflicts surfaced to a human.
- Earn the v3.0 stamp by changing the **trust contract** — enforced, real-service-proven, durably correct, externally audited.
- Ship the **trust artifact**: the published Jepsen-style convergence stress-proof + the external security-audit report, with a stated guarantee.
- Hold the anti-bloat charter at GA: **no new pillar ships.** Every line below either closes a named convergence/safety gap or hardens what already shipped.

## Scope — IN
- **[new·P0] Live 3-way merge of an external git push into an OPEN room.** Base = last-synced commit (the room's HEAD at load), ours = live Yjs buffers (`getFiles(doc)`), theirs = the pushed ref. Clean hunks apply automatically as origin-tagged `{ kind:'git-merge' }` transactions; overlapping hunks become conflict regions (Slice B). The whole reconcile runs **inside `withRoomLock(roomId, …)`** so it serialises against flush/commit/snapshot. **Behind the `ICE_LIVE_MERGE` flag (default OFF); when OFF, the existing `onLoadDocument` data-loss guard stays the fallback** (today: a non-empty doc is never overwritten by git HEAD — the push lands in the bare repo but is not merged until the next empty-doc load). **Lands DEAD LAST; gated by Slice C.**
- **[new·P0] In-editor conflict-resolution UX** (accept theirs / keep ours / per-hunk merge) built on the **v2.3 conflict-region primitive** — conflicts surfaced to a human in `SourceControl.tsx`/editor gutter, **never silently auto-resolved**. A side never disappears: until a human resolves, both versions are retained in the conflict region.
- **[new·P0] Convergence STRESS / chaos harness (Jepsen-style).** N real-ish agents (replayed transcripts from v2.2) + N humans + external pushes hammering the same files under injected network jitter, reconnects, and an external-push storm; asserts **zero divergence across Yjs↔FS↔git** and **zero lost edits** after quiescence. This is the **gating bar** for Slice A and ships as a **published result** in the trust artifact.
- **[new·P0] External security audit** (OWASP Top 10 + STRIDE) of the three named surfaces — **agent-runs-code** (`agent/`, `terminal/`, `mcp/`), the **git server** (`git/server.ts`), the **voice-token mint** (`voice/token.ts`) — plus **room↔room isolation** tests, **invite/token hardening** (`auth.ts`), and an **agent approval-gate-bypass adversarial pass**. Fix what it finds; track findings to closure.
- **[new·P1] Opt-in tamper-EVIDENT append-only audit export** — a hash-chained external sink that mirrors `getAudit(doc)` entries off-box so the trail can be verified after the fact. **NOT** an in-core crypto ledger; off by default, enabled by env. Closes the one accountability gap the threat model admits (§4.1 / §"audit trail integrity").
- **[debt·P1] Promote the v2.2 real-service verification into a maintained, documented integration suite** (the repeatable production-trust contract) + a **"production self-host" golden-path doc** (`docs/SELF_HOSTING.md` extension or new `docs/PRODUCTION.md`).
- **[new·P0] v3.0 GA stamp** — a tagged, e2e-in-CI, security-reviewed release that **publishes the stress-proof + audit results as the trust artifact** and **states the guarantee**: *no lost edits, no silently-wrong commits, every agent action attributable + enforced.*

## Scope — OUT (deferred / not this release)
- Everything in the v3 [OUT list](../../docs/ROADMAP_V3.md#explicitly-out-of-v3-the-charter-holds). Stay disciplined even at GA — **no new pillars.**
- **A2A / inter-agent bus** — declined at v2.0 (ADR; `docs/A2A_EVALUATION.md`). The shared doc + orchestrator + v2.3 intent-locks are the substrate.
- **Agent memory store + same-file LLM subtask decomposition** → v3.x. Both stack new intelligence on a base only just proven; same-file decomposition depends on v2.3 intent-locks being shown safe first.
- **Auto-resolving merge conflicts / "smart merge" heuristics beyond clean-hunk application** — out by charter: a human resolves overlaps. Clean (non-overlapping) hunks apply automatically; anything that touches the same region is surfaced, never guessed.
- **In-core tamper-PROOF crypto ledger, heavyweight observability stack (Grafana/tracing as default), admin dashboard** — the export (Slice E) is the chosen durability move; v3 observability stays the minimal `/metrics`+logs seam from v2.2.
- **Auto-merge on push when the room is CLOSED via a background 3-way merge** — when no live doc is open, the push lands in the bare repo and the existing empty-doc `loadRoomFromGit` path reconciles it on next open. Slice A only handles the **open-room** case (the genuinely new, hard one). Closed-room is already correct.
- **Forgejo-side / forge merge UI** — ICE's merge is the in-room convergence merge, not a forge PR. Forgejo stays the optional external forge (ADR-007).

## Build slices (parallelizable via worktrees)
> Slice 0 (contracts/scaffold) lands on the working branch FIRST so every worktree builds against stable interfaces, exactly as v0.1→v2.0 were built ([AGENT_HANDOFF.md](../../docs/AGENT_HANDOFF.md) §2). Then A/B/C/D/E fan out into `.worktrees/v3_0-*` on branches `v3_0-*`, then integrate back. **A is the load-bearing, most concurrency-subtle build in the entire project — it integrates LAST and only after C is green against it.**

Decoupling principle (same as prior releases): each slice **owns disjoint files** and depends on siblings **only through an injected interface or a shared type in `packages/shared`**, never by reaching into a sibling's internals. The merge engine (A) is consumed by the web (B) purely as doc state (`{ kind:'git-merge' }` transactions + conflict-region markers) and one new route; the harness (C) drives A through the **public HTTP + sync surface only** (no white-box hooks), so C stays honest about what an external client can actually do.

### Slice A — Live 3-way external-push merge ⭐ LOAD-BEARING
**Owns / edits:**
- `apps/server/src/convergence/merge.ts` *(new)* — the merge engine. Pure, lock-agnostic, fs/git-pure (mirrors how `git.ts` is path-pure):
  - `computeMergePlan(base: FileContent[], ours: FileContent[], theirs: FileContent[]): MergePlan` — per-file 3-way diff (line-based, reuse a small diff3 — `isomorphic-git` is already a dep; if it lacks diff3, vendor a minimal MIT diff3 into `packages/vendor/` à la the v2.1 `y-codemirror.next` vendoring, license-stamped). Non-overlapping hunks → `clean`; overlapping → `conflict`.
  - `applyMergePlan(doc, plan)` — apply every **clean** hunk to `getFileText(doc, path)` inside ONE `transactWithOrigin(doc, { kind:'git-merge', pushRef, baseCommit }, …)`; write each **conflict** hunk into `getConflicts(doc)` as a `ConflictRegion` (both sides retained). **Never** touches the filesystem — same law as the adapter.
- `apps/server/src/convergence/convergence.ts` — add `mergeExternalPush(roomId, doc, opts)` + `planExternalMerge(...)`: read `theirs` from the pushed ref via `readHeadFiles`-style helpers in `git.ts`, read `base` from the room's last-synced commit (persist it — see below), snapshot `ours` from the doc, call the engine, apply under **`withRoomLock`**, then record audit (`action:'git-merge'`, actor `{kind:'system'}`, detail `${theirsCommit.slice(0,8)} → ${applied} applied / ${conflicts} conflicts`).
- `apps/server/src/convergence/git.ts` — add `readRefFiles(roomId, ref)` (generalise `readHeadFiles` to an arbitrary ref) and `resolveRef(roomId, ref)`; add **last-synced-commit bookkeeping** (`getRoomBaseCommit`/`setRoomBaseCommit` — persisted in the bare repo as a ref like `refs/ice/synced-base`, set on every `flushAndCommit` and on `loadRoomFromGit`). The base is what makes the merge a real 3-way instead of a lossy 2-way.
- `apps/server/src/git/server.ts` — add a **push hook**: wrap the `node-git-server` engine's `push` event. node-git-server applies the push to the bare repo, then we detect the new ref. On push completion for room R: if a **live doc is open** for R (`getRoomDoc(R)` returns non-null) **and** `isLiveMergeEnabled()`, enqueue `mergeExternalPush(R, doc, { pushRef, theirsCommit })`. If no live doc is open, do nothing (closed-room path already correct via `loadRoomFromGit`). The hook must **not** block the git client response on the full merge (push succeeds at the git layer; the merge streams into the live doc asynchronously under the lock) — but it must record that a merge is pending so the chaos harness can await quiescence.
- `apps/server/src/realtime.ts` — update the `onLoadDocument` comment/guard: the "merging external pushes is deferred" note (lines ~120-123) is now **implemented** behind the flag; keep the empty-doc seed path; when the doc is non-empty AND `ICE_LIVE_MERGE` is on, the push hook (not load) drives the merge. Document the new invariant.
- `apps/server/src/api.ts` — add `POST /api/rooms/:roomId/merge/:conflictId/resolve` (body `{ resolution: 'ours'|'theirs'|'manual', content? }`) and `GET /api/rooms/:roomId/merge` (the current `MergePlan`/conflicts), mirroring the existing `/commit` route's `openDirectConnection` pattern. Resolution clears the `ConflictRegion` from `getConflicts(doc)` and applies the chosen text under a `{kind:'human', participantId}` transaction.
- `apps/server/src/config.ts` — read `ICE_LIVE_MERGE` (default off).
- Tests: `apps/server/src/convergence/merge.test.ts` (engine: clean-merge identity, disjoint-hunk auto-apply, overlapping-hunk → conflict, delete/rename edge cases, the load→push→merge→flush round-trip is loss-free), and extend `convergence.test.ts` for the lock-serialised path.

**Exports (consumed by siblings):** `mergeExternalPush`, `planExternalMerge`, `isLiveMergeEnabled`, the `/merge` routes, and the doc-level `{kind:'git-merge'}` transactions + `getConflicts(doc)` state. **Decouples:** B sees A only as doc state + two routes; C drives A only through git-push + sync + the resolve route (black-box). A imports nothing from B/C/D/E.

**Why load-bearing + why last:** this is the one path that can violate ADR-000 ("a collaborative IDE that loses your code"). It is the largest, most concurrency-subtle build. It integrates only after Slice C's chaos harness is green against it, behind a default-off flag, conflict-surfacing-first, with the existing data-loss guard as the fallback.

### Slice C — Convergence STRESS / chaos harness (Jepsen-style) 🚧 the gating bar
**Owns / edits:**
- `apps/web/scripts/v3_0-chaos-check.mjs` *(fills the Slice 0 stub)* — the harness, extending the existing `*-check.mjs` pattern (`HocuspocusProvider` + `Y.Doc` clients, real HTTP routes — see `v0_5-agent-check.mjs`). It spins up: M human-ish `Y.Doc` clients editing overlapping ranges of shared files; K agent clients **replaying v2.2 transcripts** (keyless, via the v2.2 replay harness) so "agents" are real-shaped; and a pusher loop that clones the room repo and `git push`es conflicting + clean changes on an interval. It injects **jitter** (randomised provider connect/disconnect, delayed flushes) and **reconnect storms**. After a quiescence window it asserts the **convergence invariant**: load the doc, `flushAndCommit`, clone the bare repo, and assert **Yjs files == FS working tree == git HEAD** for every path, and that **no edit that was acked is missing** (track a per-client edit ledger; every acked op must be present or explained by a recorded conflict resolution). Emits a machine-readable result (`chaos-result.json`) for the trust artifact.
- `apps/server/src/convergence/chaos.harness.ts` *(new, optional server-side helper)* — a thin deterministic-seed driver + invariant checker importable by both the script and a CI unit-mode (small N, fixed seed) so the harness also runs as a fast `*.test.ts` gate, not only as the heavy published run.
- `scripts/run-chaos.mjs` *(new top-level)* — orchestrates boot + the harness + teardown for CI's `chaos` job and for the published-result run (large N).
- `docs/CONVERGENCE_STRESS.md` *(new)* — methodology + how to reproduce + the published result (the trust-artifact half).
- Tests: the harness IS the test; add a fast seeded `chaos.harness.test.ts` (small N) to the server suite so regressions are caught per-PR, with the full large-N run as the gating/published job.

**Exports:** the invariant checker + result format. **Decouples:** drives A through the **public surface only** (git push, `/sync`, `/commit`, `/merge` routes) — zero white-box access, which is the whole point (it must prove what a real external client experiences). It does not import A's internals.

**Gate:** Slice A does **not** integrate to the working branch until C (large-N) is green against A's branch. C is built in parallel with A but is the **release gate** for A.

### Slice E — Tamper-evident audit export + integration-suite promotion + GA docs
**Owns / edits:**
- `apps/server/src/audit/export.ts` *(new)* — `HashChainedAuditSink implements AuditSink`: each appended `AuditEntry` is hashed with the prior entry's hash (`prevHash → entryHash`, SHA-256 over a canonical serialization) and written append-only to an external sink (file/HTTP, configured by `ICE_AUDIT_EXPORT_URL`/path). Includes a `verifyChain(entries)` function (the tamper-evidence check) and is **off by default**. **NOT** an in-core ledger — it's a one-way mirror of `getAudit(doc)`.
- `apps/server/src/audit/recorder.ts` — accept the injected `AuditSink` (declared in Slice 0); on each `recordAudit`, also `void sink.append(entry)` (fire-and-forget, never blocks the doc write). Default sink stays no-op.
- `apps/server/src/audit/index.ts` + `apps/server/src/index.ts` — construct + inject `HashChainedAuditSink` when `ICE_AUDIT_EXPORT_*` is set; log status (alongside the existing scale/ext boot log).
- `docs/PRODUCTION.md` *(new)* — the **"production self-host" golden-path doc**: real-service config (Postgres-primary, Redis 2-node, LiveKit, OIDC, BYO-key agent), the audit-export setup, the `ICE_LIVE_MERGE` flag, and how to run the maintained integration suite. Cross-link from `docs/SELF_HOSTING.md`.
- `scripts/integration-suite.mjs` *(new)* — **promote** the v2.2 real-service tier into a single maintained, documented entry point (compose up the real-service profile + run the real-agent/LiveKit/OIDC/Postgres/2-node-Redis assertions). This is the repeatable production-trust contract.
- `docs/THREAT_MODEL.md` / `docs/AGENT_HANDOFF.md` — note the audit-export as the durability move (already foreshadowed in the v3 OUT list).
- Tests: `audit/export.test.ts` — chain integrity, tamper detection (mutating one entry breaks `verifyChain`), no-op-when-disabled, append failure never breaks `recordAudit`.

**Exports:** `HashChainedAuditSink`, `verifyChain`, the integration-suite entry point. **Decouples:** consumes only the Slice 0 `AuditSink` interface; touches its own `audit/export.ts` + injection points. Independent of A/B/C.

## Sequencing + dependencies
**Cross-release gates (do NOT start v3.0 until all hold):**
1. **v2.1 CI green on a clean machine** + policy **enforcement** live (the merge runs in a world where a denied agent call already can't land) + **node-sound lock** (the merge serialises across nodes via the same lease — v3.0 leans entirely on this; a process-local mutex is not enough once `ICE_LIVE_MERGE` is on in a multi-node deploy).
2. **v2.2 real-agent path verified** + the **replayable transcript harness** exists (Slice C reuses it to make "agents" real-shaped) + spend governor (a runaway during chaos is hard-killed).
3. **v2.3 conflict-region primitive shipped** (Slice B imports it) + durable origin/blame attribution (so a merge-applied edit is attributable end-to-end). If v2.3 shipped the reviewer-agent but **not** safe intent-locks, v3.0 is unaffected — the merge does not depend on intent-locks; it depends only on the conflict-region primitive + the lock + enforcement.

**Intra-release order:**
1. **Slice 0** lands on the working branch first (contracts compile for everyone).
2. **A, B, C, D, E fan out in parallel worktrees.** B builds against A's doc-state contract (stubbed by Slice 0) and the v2.3 primitive; C builds against the public surface; D/E are largely independent.
3. **Integration order is forced:** E and D integrate first (lowest risk, no convergence change). Then B. Then **C's harness runs against A's branch**; only when **large-N chaos is green** does **A integrate LAST**.
4. **Flag discipline:** `ICE_LIVE_MERGE` ships **default OFF**. The GA tag may ship with it off-by-default-but-documented if any residual chaos flake exists; the guarantee is stated for the flagged-on path proven by the published harness. (Decision for the builders — see open questions.)
5. **GA stamp** is the final step: tag only when CI (incl. chaos + real-service) is green, the audit is closed, and the artifact is published.

## Risks + mitigations (this release)
- **R1 — the merge violates ADR-000 (lost/clobbered edits): the existential risk.** *Mitigation:* DEAD-LAST sequencing on the hardened base; engine is conflict-surfacing-first (overlaps are NEVER auto-resolved); every merge under `withRoomLock`; default-OFF `ICE_LIVE_MERGE` with the existing empty-doc guard as fallback; integration blocked until the large-N chaos harness (Slice C) proves zero divergence + zero loss. The guarantee is only stated for what the published harness proves.
- **R2 — the node-local lock is not enough.** With `ICE_LIVE_MERGE` on across multiple nodes, a push handled on node-1 must serialise against a flush on node-2. *Mitigation:* hard-depend on the v2.1 node-sound lock (Redis lease / sticky room ownership). If a deploy is multi-node, the merge MUST take the same cross-node lease; the chaos harness includes a 2-node real-Redis configuration. If v2.1's lock is sticky-room-only (not a lease), `ICE_LIVE_MERGE` is **single-node-only** until a lease lands — state this in `docs/PRODUCTION.md`.
- **R3 — base-commit drift.** A real 3-way merge needs the *correct* base (last-synced commit). If the base is wrong, the merge degrades to a lossy 2-way and may resurrect deleted files or miss conflicts. *Mitigation:* persist `refs/ice/synced-base` on every flush + load; `merge.test.ts` asserts the base is exactly the doc's load-point; the harness asserts no resurrected/lost files.
- **R4 — push-hook timing in `node-git-server`.** The push must be reconciled *after* the bare repo updates the ref but the git client response must not hang on the merge. *Mitigation:* push succeeds at the git layer; the merge enqueues asynchronously under the lock; the hook records a pending-merge marker so the harness (and `/merge`) can await quiescence. Validate the exact node-git-server hook semantics early (open question O1).
- **R5 — diff3 quality.** A naive line-merge produces spurious conflicts (noisy UX) or misses semantic overlaps. *Mitigation:* line-based diff3 with conservative conflict bias (when in doubt, mark conflict — surfacing a false conflict is safe; auto-applying a false clean is not); vendor a tested MIT diff3 if isomorphic-git's is insufficient; tune against the harness's noise metric.
- **R6 — audit-export back-pressure.** A slow/unreachable export sink must never block or break `recordAudit` (the doc-array trail is the source of truth; the export is a mirror). *Mitigation:* fire-and-forget `void sink.append()`, bounded queue, drop-with-warning on overflow; `export.test.ts` proves a failing sink leaves `recordAudit` behaviour unchanged.
- **R7 — GA scope creep at the finish line.** "While we're stamping GA, let's just add X." *Mitigation:* the OUT list is binding even at GA; any new idea is flagged for a post-v3 council (AGENT_HANDOFF §2). The GA stamp adds **no** product surface.

## Open questions (for the builders)
- **O1 — push-hook seam:** does `node-git-server`'s `push` event fire **post-ref-update** with the new ref resolvable, and can we run async work without holding the client connection open? If the event is pre-update or unreliable, fall back to a post-receive comparison (snapshot HEAD before/after `handleGitRequest`). Resolve this **first** in Slice A — it gates the whole design.
- **O2 — base reconstruction for never-flushed rooms:** if a room was opened, edited live, but never committed, there is no "last-synced commit" distinct from the empty/initial HEAD. Is the base then the initial HEAD (treat all live edits as "ours" vs an empty base)? Confirm the degenerate case is loss-free in `merge.test.ts`.
- **O3 — flag default at GA:** ship `ICE_LIVE_MERGE` **on** by default at the GA tag, or **off-but-documented** with the guarantee stated for the flagged-on path? Decide based on the chaos harness's flake rate. Roadmap intent is "behind a flag"; lean OFF-by-default unless the harness is rock-solid.
- **O4 — conflict granularity:** per-hunk vs per-file conflict regions. Per-hunk is better UX but more state in `getConflicts(doc)`. Align with whatever granularity the v2.3 conflict-region primitive already renders (don't diverge from it).
- **O5 — "agents" in the chaos harness:** is replaying v2.2 transcripts faithful enough, or does the gating bar require ≥1 **live** real ACP agent in the storm (maintainer-box run)? Recommend: seeded transcripts for the CI/published run (deterministic, keyless) **plus** one documented maintainer-box run with a live agent for the GA artifact.
- **O6 — multi-node merge ownership:** with sticky-room ownership, the node that owns room R should also own its push-merge. Does the push (which may hit any node's git server) get routed to R's owner, or does the owner poll? Confirm against v2.1's lock implementation before enabling multi-node `ICE_LIVE_MERGE`.
