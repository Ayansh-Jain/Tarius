# v0.1 — Two friends, one live file

**Status:** ✅ done (2026-05-31) — built via 4 worktree slices, merged, verified.
**Depends on:** foundation (done)
**Demo (definition of done):** Run `docker compose up` (or `pnpm dev`). Open the room URL in two browser windows, set two names. Typing in one shows up live in the other within ~100ms, each with a **named, colored cursor**. Kill the server and restart — the document is still there. Drop the network briefly — edits resync without loss.

## Goals
- Deliver the 10-second wow: open a link → see your friend's named cursor moving in the same file.
- Prove **durable** shared editing on a one-command self-host before anything else is added.
- Establish the server-side workspace substrate (real filesystem) every later pillar stands on.

## Scope — IN
- Server-side workspace on a real filesystem (single repo/dir) in `apps/server`.
- CodeMirror 6 editor with Yjs + `y-codemirror.next` shared editing and multiplayer cursors/selections/presence (awareness).
- Hocuspocus sync server with durable rooms that survive a restart (SQLite persistence).
- Share-a-room-by-link with invite links; basic email/password auth; **no mandatory account to join** via link.
- Reconnection that survives a dropped socket and resyncs without losing edits.
- `docker compose up` self-host (web + server) with zero required config, secrets auto-generated.
- Repo licensed Apache-2.0 day one, with DCO and no CLA.

## Scope — OUT (deferred)
- Git server, multi-file tree (→ v0.3). AI agents (→ v0.5). Voice/chat (→ v1.0). OIDC/Postgres/roles (→ v1.0).
- Single shared file/buffer is acceptable for v0.1; a real file tree is v0.3.

## Build slices (parallelizable via worktrees)

**Slice 0 — contracts + scaffold (on `main` FIRST, no worktree).** Everything depends on this; it must be stable before fan-out.
- `packages/shared`: protocol/domain types + Yjs doc schema helpers (the vocabulary in ARCHITECTURE.md → "Yjs document model").
- App skeletons: `apps/web` (Vite + React 19 + TS + Tailwind) and `apps/server` (Node 22 + TS) that build and typecheck empty.
- Root wiring: ensure `pnpm install`, `pnpm -w typecheck`, `pnpm -w build` work across the workspace.

**Then fan out (each in its own worktree, against Slice 0 contracts):**
- **Slice A — server:** Hocuspocus sync server, SQLite persistence (durable rooms), auth hook (room access), email/password + invite-link issuance/verification, room model.
- **Slice B — web:** React app shell, CodeMirror 6 editor bound to a shared `Y.Text` via `y-codemirror.next`, awareness-based remote cursors/selections/name/color, join-by-link flow, connection/reconnection handling.
- **Slice C — self-host:** `docker-compose.yml`, `apps/web` + `apps/server` Dockerfiles, first-boot secret generation, zero-config defaults; `pnpm dev` for local.
- **Slice D — project meta:** `LICENSE` (Apache-2.0), `CONTRIBUTING.md` with DCO, `NOTICE`, basic GitHub templates; **vendor + pin + license-stamp `y-codemirror.next`** (risk #5).

**Integrate:** merge worktrees to `main`, wire web↔server, `pnpm typecheck`/`build`, run the manual demo.

## Notes / decisions discovered
- Server is **single-port**: Hocuspocus owns the http.Server; Hono REST is swapped in as the request listener, so `/api/*` (REST) and `/sync` (WS, document = roomId) share one port. (apps/server/src/index.ts)
- Metadata DB uses Node's built-in `node:sqlite` (no native compile); Yjs doc durability uses `@hocuspocus/extension-sqlite` (better-sqlite3, prebuilt).
- `y-codemirror.next` is pinned (@0.3.5) and load-bearing — **vendoring is a tracked follow-up** (docs/DEPENDENCIES.md).
- Web bundle is ~730 KB (CodeMirror+Yjs+Hocuspocus); code-splitting deferred (perf pass, not a v0.1 blocker).
- Full `docker compose up --build` image build was not executed in this environment (compose config validated); run it on first real self-host.
